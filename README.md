# RH—MUSIC

Полноценный музыкальный веб-сервис: регистрация и вход, личная библиотека, плейлисты,
история прослушивания и **персональные рекомендации, построенные на реальной активности**
пользователя. Поиск и воспроизведение работают по каталогу Zvuk через прокси Cloudflare Worker.

* **Сайт:** https://rh-music.pages.dev
* **API:** https://rh-music.pages.dev/api (тот же домен, что и сайт — см. «Архитектура»)
* **Worker:** https://rh-music-api.rh-launcher.workers.dev
* **Репозиторий:** https://github.com/RAHER458/rh-music

## Архитектура

```
iPhone / браузер
      │  HTML + CSS + JS  (Cloudflare Pages: rh-music.pages.dev)
      │  /api/*  ──►  Pages Function (_worker.js)  ──►  Worker rh-music-api
      ▼
Cloudflare Worker  rh-music-api
      ├── каталог: GraphQL (секрет ZVUK_TOKEN) → подписанный MP3 → Range/206
      └── данные сервиса: Cloudflare D1 (аккаунты, библиотека, плейлисты, история, аффинити)
```

Зачем прокси через Pages: сессионная cookie должна быть **first-party**. iOS Safari блокирует
сторонние cookie, поэтому запросы к API идут с того же домена, что и сайт, а Pages Function
(`web/_worker.js`) перенаправляет их в Worker. Статика остаётся на существующем домене Pages.

Пароли и токены никогда не попадают в браузер: в localStorage лежат только пользовательские
настройки интерфейса (последние поисковые запросы), сессия — в HttpOnly cookie.

## Возможности

**Аккаунты.** Регистрация (имя, email, пароль, подтверждение), вход, выход, профиль,
смена пароля, удаление аккаунта вместе с данными. Проверка формата и уникальности email
и имени, понятные сообщения об ошибках.

**Моя музыка.** Сохранение треков из поиска, списков, страниц альбомов и из плеера.
Повторное добавление не создаёт дубликатов (`PRIMARY KEY (user_id, track_id)`).
Удаление убирает только запись из личной библиотеки. В библиотеке есть поиск, сортировка
и воспроизведение всех сохранённых треков.

**Плейлисты.** Создание, переименование, описание, удаление, добавление и удаление треков,
изменение порядка, воспроизведение и перемешивание. Обложкой служит обложка первого трека —
никаких загрузок файлов и платного хранилища. Удаление трека из библиотеки не удаляет его
из плейлистов.

**История прослушивания.** Записывается при старте трека и подтверждается порциями:
каждые ~25 секунд воспроизведения и при паузе/завершении/уходе со страницы. Хранятся
длительность прослушивания и факт завершения. История видна в разделе «Недавние».

**Рекомендации.** Никаких заранее заданных списков исполнителей и запросов: разделы
строятся только по данным аккаунта — прослушивания (количество, длительность, завершения,
давность), библиотека и плейлисты. Каталог используется как источник похожих исполнителей
(`relatedArtists`) и релизов, данные подтягиваются пакетно (1–2 запроса на всю страницу).
Разделы: «Продолжить прослушивание», «Для вас», «Похоже на …», «Новые релизы»,
«Популярно на RH—MUSIC» (реальная агрегированная статистика сервиса, появляется только
когда данных достаточно). Новому пользователю показывается честное пустое состояние.

**Плеер.** Поиск, воспроизведение, пауза, переключение треков, перемотка, очередь,
перемешивание, повтор, Media Session (экран блокировки), Now Playing на весь экран.
Качество фиксировано: всегда MID (MP3 128 кбит/с) — переключателя качества в интерфейсе нет.

## Структура D1

| Таблица | Назначение | Ключи и индексы |
|---|---|---|
| `users` | аккаунты: имя, email, хеш и соль пароля, число итераций | уникальные индексы по `username`, `email` (COLLATE NOCASE) |
| `sessions` | сессии: SHA-256 хеш токена, срок, ip/UA | PK `id`, уникальный `token_hash`, индексы `user_id`, `expires_at` |
| `library_tracks` | сохранённые треки | PK `(user_id, track_id)` — дубликатов нет, FK → `users(id)` ON DELETE CASCADE |
| `playlists` | плейлисты | FK → `users(id)`, индекс `(user_id, updated_at)` |
| `playlist_tracks` | треки плейлиста и порядок | PK `(playlist_id, track_id)`, FK → `playlists(id)`, индекс `(playlist_id, position)` |
| `listening_history` | история прослушивания | FK → `users(id)`, индексы `(user_id, started_at)`, `(track_id, started_at)` |
| `user_track_affinity` | агрегат по треку для рекомендаций (плейсы, секунды, завершения) | PK `(user_id, track_id)`, индексы по давности/плейсам/исполнителю |
| `user_preferences` | повтор и перемешивание | PK `user_id` |
| `auth_attempts` | ограничение частоты входа и регистрации | индекс `(ip, action, created_at)` |

Миграции: `worker/migrations/*.sql`, применяются `node scripts/db-migrate.mjs`.

## Безопасность

* Пароли — **PBKDF2-SHA256**, 100 000 итераций, индивидуальная соль; сравнение хешей выполняется за постоянное время.
* Сессия — 32 случайных байта; в базе хранится только SHA-256 хеш токена.
* Cookie `HttpOnly; Secure; SameSite=Lax` — токен недоступен из JavaScript.
* CSRF — проверка `Origin` + обязательный заголовок `X-RH-Request` на всех изменяющих запросах.
* Ограничение частоты: регистрация ≤ 6 / 30 мин, вход ≤ 12 / 15 мин на IP.
* Единый ответ «Неверный логин или пароль» и выравнивание времени ответа (защита от перебора аккаунтов).
* Все данные фильтруются по `user_id`; обращение к чужому плейлисту или треку возвращает 404.
* Значение `ZVUK_TOKEN` не читается и не выводится ни в одном ответе.

## Деплой

```bash
export CLOUDFLARE_API_TOKEN=...        # Workers Scripts:Edit, Pages:Edit, D1:Edit
export CLOUDFLARE_ACCOUNT_ID=...
export D1_DATABASE_ID=...              # id базы rh-music-db
export ZVUK_TOKEN=...                  # только при первой установке секрета

node scripts/db-migrate.mjs            # миграции D1
node scripts/deploy-worker.mjs         # Worker + D1-биндинг (секрет сохраняется)
node scripts/deploy-pages.mjs          # статика + Pages Function (прокси /api)
```

`scripts/deploy-worker.mjs` передаёт `keep_bindings: ["secret_text"]`, поэтому обновление
кода не стирает `ZVUK_TOKEN`. Автодеплой — `.github/workflows/deploy.yml`
(workflow_dispatch или пуш в `main`).

## Ограничения

* Проект неофициальный и не связан с Zvuk.com; для работы нужен собственный токен каталога.
* Раздела «Популярное» может не быть, пока в сервисе мало прослушиваний — это честное поведение,
  а не отсутствие функции.
* Аудиофайлы нигде не сохраняются: плеер получает подписанный поток по Range и не кэширует его.
